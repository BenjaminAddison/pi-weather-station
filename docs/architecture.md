# Architecture

## The pieces

```
 Owner's PC (Windows / Linux)                         WeatherPi (Pi Zero W)
┌───────────────────────────────┐   USB cable    ┌──────────────────────────────────┐
│ WeatherPi Companion (PySide6) │  RNDIS / ECM   │ usb0  10.12.194.1/28 (DHCP srv)  │
│  ├ host checks (driver, TS)   │◄──────────────►│ weatherpi-agent  :8765 (HTTP)    │
│  ├ agent client ──────────────┼── HTTP ───────►│  ├ claim / password / ssh key    │
│  ├ SSH (debug, optional)      │                │  ├ wifi (nmcli)                  │
│  ├ backups → local folder     │                │  ├ tailscale (up/serve/status)   │
│  └ AI help pack               │                │  ├ sensors live, diagnostics     │
│                               │                │  └ backup export                 │
│ Tailscale client ─────────────┼── tailnet ────►│ tailscale0 (agent + SSH + :443)  │
└───────────────────────────────┘                │ weatherpi-logger  → SQLite       │
                                                 │ weatherpi-web     :8080 dashboard│
           Browser ── https://weatherpi.<tailnet>.ts.net (tailscale serve → :8080)   │
                                                 └──────────────────────────────────┘
```

- **Image** (`image/`): stock Raspberry Pi OS Lite 32-bit (Trixie, 2026-10-06), customised in a privileged Docker builder container. Output is a `.img.xz` you flash as-is.
- **Pi software** (`pi/`): the v1 logger and dashboard, plus a new **agent**, a small HTTP API that the app drives. See [pi-software.md](pi-software.md).
- **Companion app** (`app/`): an installed desktop app. See [companion-app.md](companion-app.md).
- **Contract:** [pi-agent-api.md](pi-agent-api.md). The app and the agent are built and tested against it independently.

## Connection modes

| Mode | Link | Used for |
|---|---|---|
| **Setup** | USB cable (RNDIS, `10.12.194.1`) | First-time setup only: claim, password, WiFi, Tailscale login on both devices. Also recovery (forgotten password) and re-doing WiFi if the Pi has lost its network. |
| **Monitoring** (normal operation) | **Tailscale** (`weatherpi.<tailnet>.ts.net` / `100.x`) | Everything after setup: live status and sensors, the dashboard, backups, diagnostics and the AI help pack, password change, reboot. Works from anywhere; no cable needed. |

Setup isn't finished until the app has reached the agent **over Tailscale** (the last check in the wizard). After that, the app's home screen connects over Tailscale by default and falls back to USB only if it's plugged in.

## Security model

1. **Unclaimed Pi.** A freshly flashed Pi has `main` with a **locked password**, no SSH keys, and the agent listening **only on `usb0`**. Being physically connected over the cable is what authorises the first step.
2. **Claim** (one time, over USB only). The app sends:
   - the owner's chosen **password**, which becomes `main`'s login and sudo password;
   - the app's **SSH public key** (an ed25519 keypair the app generates);
   - an **API token** (a random 32 bytes the app generates; the Pi stores only its SHA-256);
   - a **recovery password** (random, generated by the app). The Pi stores only its hash (see D6).

   After the claim, `/claim` returns 409 for good.
3. **After the claim**, every agent endpoint except `GET /v1/info` needs `Authorization: Bearer <token>`. The agent listens on `usb0` and `tailscale0` only, never on WiFi (`wlan0`).
4. **Forgot the password:** the app uses the stored recovery password (over USB) to set a new one. If the app data is lost too, the only option is a **factory reset**: re-flash the card, or hold the reset method described in D7.
5. **Secrets on the PC** are kept in the app's data folder (`%LOCALAPPDATA%\WeatherPi\` on Windows, `~/.local/share/weatherpi/` on Linux): the private key, API token and recovery password. On Windows they're encrypted at rest with DPAPI (current user). The owner's own password is **never stored**.
6. **SSH:** key login (the app key) is always allowed. Password login is allowed only after the claim (D8).

## Decisions

Status: **D** = decided, **P** = proposed (change freely), **O** = open (needs a decision).

| # | Decision | Status | Notes |
|---|---|---|---|
| D1 | Base OS: Raspberry Pi OS Lite **armhf** (32-bit) Trixie 2026-10-06 | D | The Pi Zero W is ARMv6, so 64-bit won't run. The image is pinned by sha256 in `image/base.env`. |
| D2 | USB networking uses the stock **`rpi-usb-gadget`** (g_ether, RNDIS+ECM, Pi at `10.12.194.1/28`), switched on in the image | D | Replaces v1's custom configfs NCM and the mass-storage gadget. |
| D3 | The USB instructions drive is **dropped**; the Companion app replaces it | D | No more `wifi.img`, `wifi-watch`, `usb-template`. |
| D4 | The Windows RNDIS driver (`rpi-usb-gadget-driver-setup.exe`) is **bundled** and installed by the installer if missing | D | Licence check is a task in W5. |
| D5 | App stack: **Python 3.12 + PySide6 (Qt 6)**, packaged with **PyInstaller (onedir)** and installed with **Inno Setup** | P | One language across the project. Alternatives: .NET + Avalonia, Go + Fyne. |
| D6 | "Backup password" means an app-generated **recovery password**, stored in the app data folder, that authorises `POST /v1/recover` over USB to set a new owner password | D | Confirmed by the client (2026-10-19). |
| D7 | Factory reset without the app data: re-flash the card. A "hold the rain bucket tipped at boot" reset is a possible later addition | P | |
| D8 | SSH: key auth always on; password auth turned on at claim time | P | Lets the owner or an AI helper SSH in with the chosen password. |
| D9 | Agent: Python **FastAPI + uvicorn** from Debian packages, port **8765**, bound to `usb0` and `tailscale0` | P | |
| D10 | All Python dependencies on the Pi come from **apt** (`python3-fastapi`, `-uvicorn`, `-gpiozero`, `-lgpio`, `-yaml`), not pip or a venv | D | Packages were confirmed available in the image. Avoids ARMv7 wheels under emulation and slow pip installs on ARMv6. |
| D11 | The image ships an **empty database**. v1 data is recovered separately and kept by you | D | |
| D12 | Layout on the Pi: code in `/opt/weatherpi`, data in `/var/lib/weatherpi`, config in `/etc/weatherpi/config.yaml`; services run as system user **`weatherpi`** (groups `gpio`); the agent runs as root | P | v1 used `/home/main/weatherpi`. |
| D13 | Hostname `weatherpi` | P | Tailscale adds a `-1` suffix if the name clashes. Alternative: `weatherpi-<last 4 of serial>`. |
| D14 | Power-loss and SD-wear hardening: **read-only root** (Raspberry Pi OS overlay FS, `overlayroot=tmpfs`), with everything that must survive a reboot on a separate writable **data partition** (p3, mounted at `/data`). Also `noatime`, journald `SystemMaxUse=16M` (kept on `/data`), SQLite WAL with `synchronous=NORMAL`, nightly backup. **Maintenance mode** (agent endpoint + app switch) turns the overlay off until it's switched back on. The overlay is `overlayroot=tmpfs:recurse=0` (only `/`; the default would also wipe `/data`). Design: [pi-software.md "Read-only root"](pi-software.md#read-only-root-d14) | D | Changed 2026-10-28: read-only root is now **yes** (declined 2026-10-19). Implemented 2026-11-02 (W8), **awaiting the hardware test**. The mechanism details (overlayroot, bind mounts, committing rare `/etc` changes) are **P** until they're proven on hardware. |
| D15 | Tailscale: installed in the image from Tailscale's apt repo (armhf). Login is done through the app (AuthURL → browser) | D | The owner signs in on both devices with the **same account**. |
| D16 | Dashboard: kept on `:8080` locally and exposed with `tailscale serve` at `https://weatherpi.<tailnet>.ts.net` | D | |
| D17 | Builder: a Docker container `weatherpi-builder` (`debian:trixie`), privileged and root, only started for a build | D | Recreating the container loses the apt tools, so a Dockerfile is proposed in image-build.md. |
| D18 | Linux support for the app: **later**. Write it portably now and package it for Linux after Windows works | P | |
| D19 | Installing Tailscale on the host: the installer offers the official Tailscale installer (bundled MSI) if it's missing; the app re-checks at runtime | P | **Superseded by D25** (2026-11-01). |
| D20 | Code signing: **none** for now (SmartScreen will warn) | O | A code-signing certificate costs money. |
| D21 | App name: **WeatherPi Companion** | P | |
| D22 | The WiFi result is shown in the app; the ACT LED still blinks 3× for success and 1 long for failure as a secondary signal | P | |
| D24 | **Web dashboard = the v1 dashboard, reused** (current temperature, rain today, 24 h temperature line chart, rain-tip bar chart, online/stale status, CSV export 24h/7d/30d/all, auto-refresh). Reachable from **any device on the owner's tailnet** (phone, laptop, tablet with the Tailscale app) at `https://weatherpi.<tailnet>.ts.net`. The **Companion app also shows it**, in a built-in Dashboard tab (Qt WebEngine) plus an "Open in browser" button. Small v2 tweaks only: show rain in **mm** alongside tips, and serve Chart.js locally from the Pi instead of a CDN, so the page also works when the viewing device has no internet access | D | Client requirement (2026-10-19). |
| D26 | The owner can change **how often a temperature reading is saved** (`temp.write_interval`) from the app's **home screen**: 1, 5, 10, 15, 30 or 60 minutes (default 5). The sensor read rate follows it (`poll_interval = min(30 s, interval)`). Stored in `/var/lib/weatherpi/settings.yaml` on the data partition, so it works with the read-only root. Rain isn't affected: every bucket tip is recorded | D | Client requirement (2026-11-02). API: `GET`/`PUT /v1/settings` (agent 2.2.0). |
| D28 | **Setup and the home app are distinct.** Once setup is done the window becomes the **home app**: its own menu (Overview, WiFi networks, Measurements, Settings) and no setup step list. Settings has **Set up again…** (asks first, then the Welcome page: flash a card or use the one in the Pi). **WiFi networks** in the home app adds, reorders and removes saved networks over Tailscale, but never changes or removes the one in use (it may carry the link; that needs USB + Set up again). In setup, adding networks that aren't in range is its own **optional page** right after WiFi ("Will the WeatherPi live somewhere else?") instead of a second tab | D | Client requirement (2026-11-02). |
| D27 | **No pretend Pi.** Manual testing is done only on the physical Pi (and this PC's real driver and Tailscale). The mock agent (`tools/mock-agent`, `/__mock` hooks, `X-Mock-Via`), the app's fake host (`ui/devfakes.py`, `WEATHERPI_FAKE_HOST`) and `WEATHERPI_AGENT_URL` are removed. Automated tests keep their in-memory fakes (`FakeOS` with `WEATHERPI_FAKE=1`, `app/tests/fakes.py`) | D | Client decision (2026-11-02). |
| D23 | **USB is for setup only; regular monitoring happens over Tailscale.** Setup endpoints that need USB are marked USB-only in the API; everything else works on both links. Setup is only "done" once the app reaches the agent over the tailnet | D | Client requirement (2026-10-19). |
| D25 | Tailscale on the host is **installed by the installer** (silently, if it's missing; a task the owner can untick). The installer **downloads** the pinned MSI from `pkgs.tailscale.com` at install time and checks its sha256, rather than bundling it. If the download fails, setup carries on and the app offers the download link as before | P | Proposed by W7 (2026-11-01). Not bundled because we found no clear right to redistribute Tailscale's Windows client (its GUI isn't plainly open source); downloading also keeps the installer ~37 MB smaller. Cost: installing Tailscale needs internet, which setup needs anyway. Alternative: bundle the MSI once redistribution is confirmed with Tailscale. |

## Open questions

Answered 2026-10-19: D6 recovery password (yes), D14 read-only root (no; **changed to yes on 2026-10-28**), backups **manual only** in the app (with a reminder when the last one is more than 7 days old; the Pi's own nightly on-device backup stays).

Still open:
1. **D20:** sign the app? (Default: unsigned for now.)
2. Is **restoring** a backup needed in v2.0? (Default: yes, simple DB restore; it's already in the API.)
3. Owner-facing branding: any name or logo? (Default: "WeatherPi Companion", plain icon.)
